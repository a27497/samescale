01 · A real coding task

浏览器断流后，任务进度还能恢复吗？

一个前端任务进度页面通过 SSE 接收更新。任务尚未结束时，连接可能中断或提前结束。修复目标是自动恢复订阅，保留已知进度，并防止旧连接污染当前任务。

  1. 断流后自动重连；重试有等待上限，不形成忙循环或并行重复连接。
  2. 终态、认证失效、主动断开或切换任务后，停止旧连接的恢复。
  3. 晚到回调不能覆盖新任务状态；保留已有授权与人工操作反馈。

真实仓库级 TypeScript / Vue 修复任务。冻结 task、起始 workspace 和 independent verifier；展示不包含仓库源码或隐藏验收资产。

05 · Evidence-bounded diagnosis

事实可以复验，根因仍有边界

能确认

Codex 保存了修改、自检与独立通过记录。Claude 保存了读取和 shell 交互，随后直到时限仍无完成、文件变更或验收记录。

execution_budget_exhausted 是已记录的 failure taxonomy。

不能确认

无法证明 timeout 是模型、provider 或运行时哪一层导致。没有逐事件时间戳；thinking metadata 数量不是 token usage，也不是有效推进的证明。

root cause: NOT_ESTABLISHED

原 Claude cleanup FAIL 与随后 post-stop cleanup PASS 分开保留；后续收尾不会改写原 attempt。

把已知事实变成后续变更的回归边界

65 项离线回归 PASS · 两次 CLI replay · 5 个输出逐字节一致。

已保存的 GitHub Actions 记录：Offline Regression 与 Fast CI 均 PASS。实现验收 SHA：b2d729bc8d1c9eb793511b54a7b235a72e67cb9b。这是 2026-09-21 的已核验记录，不是实时状态。

  • evidence / digest drift 与 replay inconsistency
  • trace / schema / parser regression
  • changed-files attribution 与 failure taxonomy regression

本地与 GitHub 使用同一入口。回归运行于无外部网络的 namespace，环境清空；普通 CI 不调用 Provider、model、Claude 或 Judge。依赖安装与 GitHub 日志传输在回归隔离边界之外。

工程交付：真实 run evidence → 描述性 Trace Diff → 有边界的诊断 → 离线可复验 → CI 检测回归。S1 partial/blocked；S2/S3/S4 complete，求职展示已冻结。
