# MiniShop：独立验收，也需要复核验收标准

**Agent 自报完成不等于独立验收通过；验收标准本身也需要复核。**

2026-10-17（Asia/Shanghai），SameScale 对交付后的 MiniShop 代码进行了一次独立 L0 验收。
冻结任务 `minishop-fastapi-sqlite@1.1.2` 的历史结果是 **VERIFIED_FAIL，24/26 PASS**，
C05、C13 失败，原详情均为 **`AssertionError`**。一次物理执行，零重试。这个成绩保持不变。

| 层次 | 能确认什么 | 不能据此推出什么 |
| --- | --- | --- |
| 交付方声明 | DeepSeek 自报 pytest 91/91、HTTP 22/22、浏览器 30/30 PASS | 缺原始日志、截图和原生运行记录，不能认证自测或实际模型身份 |
| 独立运行观察 | 固定环境完成 26 项，24 PASS、2 FAIL；无基础设施失败 | 两个 FAIL 不等于两个确定的代码缺陷 |
| C05 后续裁决 | 原 R 要求最终金额由后端计算，没有要求携带额外金额字段的请求必须成功；旧检查强制 2xx，条件过严 | 不能断言此次返回了 422，不能证明信任伪造金额；也不把历史改为 25/26 |
| C13 静态推断 | 请求模型的非严格 int 转换可能使 bool 在业务层检查前变为整数；存在高置信静态证据 | 原收据未保留具体 HTTP 响应和状态变化，不能冒充运行根因已实证 |
| 两次离线 Replay | 保存证据在两次独立重建中逐字节一致 | 不重新执行应用或 Verifier，不代表重新验收通过 |

C13 的“布尔数量必须拒绝且状态不变”来自对合法商品数量的业务解释，原 R 没有逐字列出布尔值。
正式镜像锁定 **Pydantic 2.14.1**；没有用其他版本的实验替代本次证据。
原 Record 的 `NOT_VERIFIED / NO_RUN_RECORD / NOT_ATTESTED` 保持原身份，独立工作区验收另存。

## 公开验证边界

公开 JSON 是允许字段投影，**不是可匿名完整 Replay 的导出包**。源码、隐藏检查、Oracle、
资格源码、原始 export 和敏感收据留在私有存储。索引列出原件文件 SHA-256；
`receipt_digest` 是已有规范化对象摘要，不能与收据文件字节摘要混用。
读者可重算公开文件摘要、检查数字与来源关联是否一致；持有原件的授权审查者可进一步重算原件。
没有原件就不能由散列还原或独立验证其内容，散列也不认证来源真实性。
原生命周期对象只保存了摘要，完整对象没有单独保留，无法独立重算该项。

本案例不证明 DeepSeek 普遍可靠或不可靠，不做模型排名。HTTP 前端检查没有执行 JavaScript，
不覆盖购物车/浏览器结算、视觉适配、Windows、文档充分性或全部故障与并发调度。
本轮工程收口真实 MiniShop **0 次物理执行**；新资格不修订旧任务、旧资格或历史分数。
